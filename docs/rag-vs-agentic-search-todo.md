## 1. 为什么补这个实验

- 设计结论 4 "不用向量 RAG — grep/BM25 完胜" 是**推理结论**,依据是语料规模(~500KB)与查询形态(精确 token 为主),没有跑过对照实验。
- 独立框架的知识检索层选型(决策点 #2)需要实测数据支撑,不能沿用未经度量的旧结论。
- 业界出现 "agentic search 优于向量 RAG" 的实践转向(如 Claude Code 用 grep/read 工具循环替代向量检索),但该结论需要在**本项目语料与查询分布**上验证——本项目查询以寄存器名/错误码等精确 token 为主,恰好是 embedding 的弱项场景,且我们有现成 ground truth,是少见的可以做严格对照的机会。

## 2. 被测方案定义

| 方案 | 形态 | 说明 |
|---|---|---|
| A. 向量 RAG | 一次性检索 | 切块 → embedding → 相似度 top-k → 注入上下文 |
| B. Agentic search | 工具循环 | LLM 多轮发起 grep/glob/read,自行决定下一步看什么(Claude Code 式) |
| C. 现状基线 | index + grep | kb_lookup(index.yaml 关键词路由) + kb_search(精确 token grep),即 kb-mcp 现行实现 |
| C′. BM25 + grep | 稀疏检索 + grep | work-summary §1.2 设计结论 4 指名方案:BM25 稀疏召回 + grep 精确 token 复核;C 的加强版,需新实现后实测 |
| D. 混合 | A/B/C/C′ 组合 | 如 BM25 先召回 + LLM agentic 精读;或向量召回 + grep 复核 |

## 6. 评估指标与判定标准

### 6.1 评估指标(检索质量,统一定义)

以**预期文件为 gold answer**(regression.py 的预期答案即标注),对每个查询的候选排序计算:

**① 召回类指标**

| 指标 | 定义 | 回答什么问题 |
|---|---|---|
| **Recall@2** | gold 文件出现在 top-2 的查询占比;多 gold 时按 min(2, |golds|) 计分 | 现行 kb_lookup 返回 top-2,这是**上线主指标** |
| **Recall@5** | gold 文件出现在 top-5 的查询占比 | 渐进加载下多喂几个候选的成本可接受时,召回上限 |

**② 排序质量指标**

| 指标 | 定义 | 回答什么问题 |
|---|---|---|
| **Hit@1** | top-1 即 gold 的占比 | "第一跳就找对"的能力,agentic search 的关键卖点 |
| **MRR**(Mean Reciprocal Rank) | mean(1 / gold 首次出现排名);gold 不在结果记 0 | 排序质量:第一名就中 vs 垫底才中,比 Recall 更敏感 |
| **nDCG@5** | 多 gold 查询按分级相关折算(命中 gold=相关 1,未命中=0) | 答案分散类 case 的排序质量(依赖多 gold 补标注) |

**③ 鲁棒性指标(H6)**

| 指标 | 定义 | 回答什么问题 |
|---|---|---|
| **扰动衰减率 ΔRecall@2** | (干净分 − 扰动分) / 干净分,分三档报告 | 同义改写/错别字/口语化下谁更稳;关键词路由(C)是否比 BM25/embedding 更脆 |
| **措辞依赖度** | 查询词与 gold 文件触发词的字面重合率 vs 命中的相关性 | 区分"真语义匹配"与"碰上关键词" |

**④ 拒答/诚实度指标(H7)**

| 指标 | 定义 | 回答什么问题 |
|---|---|---|
| **假候选率** | KB 外查询返回了候选(且无一为 gold)的占比 | 谁更少把"不知道"包装成"找到了"——诊断 agent 硬要求 |
| **正确拒答率** | KB 外查询明确返回"无匹配/低置信"的占比 | 拒答通道是否存在且可用 |
| **AUROC(置信度区分度)** | 以候选分数区分 KB 内 gold / KB 外的能力 | 分数是否有可信阈值可做自动拒答 |

**⑤ 成本与延迟指标(H4)**

| 指标 | 定义 | 回答什么问题 |
|---|---|---|
| **端到端延迟** | 查询 → 可用候选的墙钟时间(P50/P95) | agentic 多轮与向量索引查询的实时性差距 |
| **token 成本** | 每查询消耗 LLM token(B/D 方案) | 夜批与日常使用的成本可接受性 |
| **检索器自身开销** | 非 LLM 部分的索引构建时间 / 内存占用 | BM25 与向量索引的部署成本 |

分维度统计(同一套指标按查询类别拆分,不做平均掩盖):

| 维度 | 切分 | 来源 |
|---|---|---|
| 查询类型 | 自然语言症状 vs 精确 token(寄存器名/错误码) | 对应 H1/H2 |
| 主题域 | protocols / system / vendor / reference / debug / rtos / method | 找弱域 |
| gold 分布 | 单文件 vs 多文件 | nDCG 有效性 |
| 扰动档位 | 干净 / 同义改写 / 错别字 / 口语化 | H6 |
| 语料规模 | 1x / 10x / 100x | H3 |

B 方案(agentic)按**最终推荐候选集**计分:每轮工具调用产出的 read 目标 + 最终答案中引用的文件,排名按引用顺序;中途 read 后放弃的文件不计命中——这与"agentic 更准"主张的真实含义(收敛到正确文件)一致。

### 6.2 判定标准(实验输出什么决策)

| 结果 | 决策 |
|---|---|
| B/C/C′ 在两类查询上 Recall@2 ≥ A 且 Hit@1 ≥ A、token 成本可接受(H4 通过) | 维持无 RAG;KB 渐进加载走 Skills / 索引方案 |
| A 在自然语言症状查询上 Recall@2 领先最优稀疏方案 **≥ 10 个百分点**(约 ≥ 27/274 查询) | 引入向量召回层,采用 D 混合 |
| C′(BM25+grep) Recall@2 较 C 提升 ≥ 5 个百分点且无 RAG 依赖 | C′ 成为 kb-mcp 默认检索实现,C 保留为兜底 |
| H3 存在规模阈值(10x/100x 下稀疏方案 Recall@2 跌破 85%) | 当前维持无 RAG,框架预留可插拔检索层接口,并标注阈值 |
| 任一方案 P95 延迟 > 交互可用阈值(建议 3s,C/B 以实测目标模型为准) | 该方案只用于夜批/离线,不进交互链路 |
| H6:某方案扰动衰减率 > 15 个百分点 | 该方案需前置查询归一化(同义词表/分词容错)才能上线 |
| H7:最优方案假候选率 > 20% 或无拒答通道 | 检索层必须加置信阈值 + 显式"无匹配"返回,写入工具契约("工具必须诚实"落到检索层) |

显著性的最低要求:主指标差异需通过配对检验(McNemar,Recall@2 的逐查询配对)或至少 95% 置信区间不重叠;274 查询下 10 个百分点差异约对应 27 个查询翻转,统计上可分辨。

**实验约束(沿用既有设计结论,不随实验结果改变):**

1. **确定性事实进工具** — 寄存器位含义、错误码解码永远由工具返回,不靠检索;本实验只测"第一跳怎么找到对的文件"。
2. KB 三级渐进加载结构(索引 → 症状文件 → reference)不变。
3. 各方案使用同一 LLM 与同一查询集,结果可复现(固定随机种子、记录模型版本)。
4. 鲁棒性档位与负样本的构造规则先固化再生成,避免为某方案定制措辞(评测集不偏袒)。

## 7. 实测结果（2026-10-21，实验已跑完一轮）

### 7.1 四方案主结果（全量 80 条）

| 方案 | Recall@2 | Hit@1 | MRR | P50 | P95 | 失败率 |
|---|---|---|---|---|---|---|

| A 向量 RAG | 0.8000 | 0.7250 | 0.7965 | 106 ms | 136 ms | 0% |
| C′ BM25+grep | 0.8000 | 0.6250 | 0.7296 | 0.6 ms | 1.1 ms | 0% |

### 7.2 逐条判定 §6.2 的决策表

| 决策条件 | 判定 | 依据 |
|---|---|---|
| B/C/C′ 在两类查询上均不劣于 A → 维持无 RAG | ⚠️ **部分成立** | B 两轨都不劣于 A（index +18.0pp / search +3.3pp）；但 C 明显劣于 A（−26.0pp / −50.0pp），C′ 的 search 轨 Hit@1 也劣于 A（0.7333 vs 0.9667）。**字面不成立**，其意图由 B 单独达成 |
| A 在自然语言症状查询领先最优稀疏 ≥ 10pp → 引入向量召回层 | ❌ **不成立** | A 的 index 轨 0.70 **低于** C′ 的 0.72，A 未领先 |
| C′ 较 C 提升 ≥ 5pp 且无 RAG 依赖 → C′ 成为默认实现，C 兜底 | ✅ **成立** | +35.0pp，p_adj = 9.9e−07 |
| 任一方案 P95 > 3s → 只做夜批 | ✅ **B 触发** | B P95 101.5s；A 136ms、C′ 1ms 可进交互链路 |
| H7 最优方案假候选率 > 20% → 必须加拒答通道 | ✅ **对 C′ 成立** | C′ 假候选率 100%；A 为 0%；**B 无法评估**（无负样本跑批实现） |
| H3 规模阈值 | ⚠️ 未做 | 规模实验为可选阶段 |

### 7.3 结论

1. **维持无 RAG**，KB 渐进加载走 **C′（BM25+grep）**，C 保留为兜底。
2. **不引入向量召回层**——理由比原计划更强：不是「A 没赢稀疏方案」，
   而是「**agentic 检索显著优于向量检索**」（B 比 A 高 12.5pp，p_adj = 0.039）。
   若要给检索层加投入，方向是 agentic 而非向量。
3. **B 只能做夜批/离线**（P95 101.5 秒，每条 1.9 万输入 token）；
   **C′ 是唯一的交互链路方案**（0.62ms，R@2 与 A 打平）。
4. **B 的优势不来自评测集与语料同源**——已用覆盖率分层排除：
   B 的优势不随覆盖率下降（低覆盖层 +18.8pp、高覆盖层 +23.5pp，相关系数 −0.018），
   而对照组 C′ 呈现典型的词频红利形态（低覆盖层 −12.5pp）。
