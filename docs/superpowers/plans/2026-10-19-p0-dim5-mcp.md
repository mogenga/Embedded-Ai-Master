# P0 维度 5 MCP 客户端实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 MCP stdio 客户端：user/project 配置、会话级连接、`mcp__server__tool` 命名空间、调用/结果映射、失败隔离、一次重连与 list_changed 刷新；每个 Task 完成后两轮独立 review。

**Architecture:** `src/mcp/config.ts` 加载/合并配置；`manager.ts` 管理 `@modelcontextprotocol/client` 连接与工具缓存；`tools.ts` 把 MCP 工具适配为 `ToolDef`（透传 `modelSchema`）；`runSession` 启动/关闭 manager 并刷新 registry。

**Tech Stack:** TypeScript + Node 24(ESM-only)、MCP SDK v2(`@modelcontextprotocol/client` ^2.3.1)、Zod v4、vitest v4；测试 server 用 `@modelcontextprotocol/server`(devDependency)。

**Spec:** [2026-10-19-p0-dim5-mcp-design.md](../specs/2026-10-19-p0-dim5-mcp-design.md)

## Global Constraints

- Node >= 24, ESM-only, strict, 相对导入 `.js`; 不新增除 MCP SDK 外的依赖。
- **依赖由用户手动安装**: `npm install @modelcontextprotocol/client`、`npm install -D @modelcontextprotocol/server`; agent 不执行安装。
- 配置/命令来自用户文件; 不拼接模型输入到 command/args/env。
- 工具名 `mcp__<server>__<tool>`; sanitize + ≤64 + 6 位 hash; 冲突按 server 隔离跳过。
- 单 server 失败不阻塞其他; 连接/调用错误结构化; 不无限重连。
- 每个 Task: TDD → 全量验证 → **第一轮实现 review → 修复 → 第二轮独立复核** → 通过才进下一 Task。
- 分支 `feat/p0-dim5-mcp`; 不合并 `main`。

## Review Focus

1. 配置字段级合并、`disabled:true` 继承、未知字段宽松、坏 JSON 报错。→ Task 1
2. env 默认继承 process.env; cwd 相对配置文件目录。→ Task 1
3. 单 server 连接失败隔离; 连接超时; close 回收子进程。→ Task 2
4. 同 server 串行调用（即使 readOnlyHint）；超时/取消后不保证与残留调用不重叠（见 design §4.2 / D-022）。→ Task 2
5. `inputSchema` 透传模型可见；`z.unknown()` 不触发 `toJSONSchema` 根类型错误。→ Task 3
6. 命名冲突按 server 跳过并记 status；名称 sanitize/截断/hash。→ Task 3
7. list_changed 刷新成功/失败（保留旧缓存）；重连成功也触发刷新通知；listener 抛错隔离；registry 只替换 MCP 工具。→ Task 2/4
8. runSession 无配置/disabled 不启动；`mcp.enabled:false`；status 事件。→ Task 4
