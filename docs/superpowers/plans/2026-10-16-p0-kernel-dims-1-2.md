# P0 内核维度 1+2(主循环 + 模型接入)实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可运行的 P0 内核维度 1(Agent 主循环)+ 维度 2(模型接入),自带最小会话与工具管线,"对话→模型响应→工具调用→结果回灌→终止"最小闭环本机可跑,`vitest` 断网全绿,覆盖率 ≥85%。

**Architecture:** 单一 Node 进程内,事件流形态主循环(`async function* query`)驱动:会话层 append-only JSONL 落全部事件("model-visible means logged"),模型经 `ModelProtocol`(仅 complete/countTokens)的 OpenAI 兼容实现进出,工具经五阶段管线执行并做 8k 落盘 + 25k 截断。模型视图 = 日志投影的重组(含 tool_calls 批级配对)。

**Tech Stack:** TypeScript + Node 24(ESM-only)、Zod v4、vitest v4(均经 Context7 查证)。禁引入现成 harness / pi-ai;MCP SDK 留给维度 5。依赖安装由用户手动执行，agent 不执行 `npm install`。

**Spec:** [docs/superpowers/specs/2026-10-16-p0-kernel-dims-1-2-design.md](../specs/2026-10-16-p0-kernel-dims-1-2-design.md)(B1-B4 判定均已写入本文档 §4.6 / 4.4 / 4.5,计划直接引用)

## Review Focus

规格未言明、但实现时必须钉住的行为(逐条已归入所属任务的测试):

1. `providers.json` 缺失或 JSON 损坏 → **结构化错**,不静默回退默认值(违规即失败)。→ Task 2
2. `model` 引用在 providers 中不存在 → 报错信息含合法引用列表。→ Task 2
3. OpenAI 响应 `message.tool_calls[].arguments` 为非法 JSON → **结构化错回传模型**,不是抛异常。→ Task 6
4. assistant 消息同时含 `content` 与 `tool_calls`(OpenAI 允许带头尾文本)→ 重组消息保留两者。→ Task 9
5. 大工具结果超 8k tokens → 全文落 `artifacts/<id>.txt`、事件 text 截断、`artifactPath` 非空;全文仍可从文件复原。→ Task 8
6. 批内工具全 `readOnly` → 并发执行;含写工具/无标注 → 串行(时序可测)。→ Task 8
7. `maxCostUsd` 未配置(price 表缺省)→ 只记 token 不熔断。→ Task 9
8. 会话首条必为 `system` 事件(有 systemPrompt 时),首条之前不落任何用户内容。→ Task 3
9. abort 时主循环先落 `interrupted` 事件再终止,已产出的 assistant 消息留在日志。→ Task 9
10. 未知工具名出现在 tool_use → 结构化错误回传,主循环继续或终止(由实现定,单测钉死其一即可,本计划钉:继续,记 tool_result isError=true)。

  - `interface AssistantPayload { content: string; toolCalls: Array<{ id: string; name: string; arguments: Record<string, unknown> | { error: "invalid_json"; raw: string } }> }`(B4)

  - `interface ModelChatMessage { role: ModelRole; content: string; tool_call_id?: string; name?: string; tool_calls?: Array<{ id: string; type: "function"; function: { name: string; arguments: string } }> }` — **`tool_calls` 字段(2026-10-17 经 Task 6 核验回填)**: 形取 OpenAI wire 格式(`arguments` 为字符串),供 Task 9 `buildMessages` 把 `AssistantPayload.toolCalls` 投影回 assistant 消息;适配器对 messages 原样透传,不做改写。缺该字段时 Task 9 只能 `as` 强转,故在类型层钉死。

  - `interface CompletionResult { content: string; toolCalls: Array<{ id: string; name: string; arguments: Record<string, unknown> | { error: "invalid_json"; raw: string } }>; truncatedByMaxTokens: boolean; usage?: { promptTokens: number; completionTokens: number; cachedTokens?: number }; stopReason: unknown }`
  - **响应读取契约**: 响应体**不做整体 schema 校验**,只定向读取——`content` 缺失/非字符串 ⇒ `""`;`tool_calls` 缺失 ⇒ `[]`;`usage` 缺失 ⇒ `undefined`;未知字段忽略(理由见 v0.2 §2.2;工具入参校验严格走 Zod `safeParse`,不适用本条)

  - `heuristicCountTokens(messages: ModelChatMessage[]): number` — `Math.ceil(每消息 content 字符数/4)` 求和,空数组 = 0。**口径(核验回填)**: "字符数" 指 JS `string.length`(UTF-16 code unit),非 Unicode 码点;中文 4 字计 1 token、emoji 按代理对计 2 个 code unit。该启发式对 CJK/emoji 系统性低估,属已知偏差(usage 锚定校准留后续),测试须按 `length` 语义钉死,不得按码点重写。
  - `checkBudget(messages: ModelChatMessage[], contextWindow: number): { over: boolean; tokens: number; softLimit: number }` — `softLimit = Math.floor(contextWindow * 0.8)`;`tokens > softLimit ⇒ over`。

### Task 5: 有界指数退避重试

**Files:**
- Create: `src/model/retry.ts`
- Test: `tests/retry.test.ts`

**Interfaces:**
- Consumes: 无
- Produces:
  - `interface RetryConfig { maxRetries: number; baseDelayMs: number; isRetryable: (err: unknown) => boolean; sleep?: (ms: number) => Promise<void>; rand?: () => number }`
  - `async function retry<T>(fn: () => Promise<T>, cfg: RetryConfig): Promise<T>` — 第 n 次失败后延迟 `baseDelayMs * 2^(n-1) * (0.5 + rand()*0.5)`,共 `maxRetries` 次重试;不可重试错立即抛;超上限抛最后错误。
