# M2 事件总线实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把会话日志投影为可实时订阅、可断线续传的事件流，让 Web 在诊断过程中看到工具、权限、MCP 与设备状态。

**Architecture:** 以 append-only 会话日志为唯一事实源，`LogTailEventSource` 读历史并轮询增量，`/api/events` 用 SSE 补播+跟随；新增 `tool_started`、`mcp_status`、`device_status` 事件，设备状态由 MCP `structuredContent.deviceStatus` 显式发布，总线不做推断。客户端按 `sessionId + seq` 绑定、去重、缺口重拉，并合并进同一会话事件数组。

**Tech Stack:** TypeScript + Node 24（ESM-only）、Node HTTP/`EventSource`、vitest；不新增依赖。

**Spec:** `docs/superpowers/specs/2026-10-19-event-bus-design.md`

## Global Constraints

- TypeScript + Node 24，ESM-only，相对导入必须带 `.js`，strict；不引入 CommonJS。
- 不新增依赖；测试默认离线；不得真实执行危险命令。
- 会话日志是唯一事实源；所有实时事件先成功落日志（`append`）再投影。
- 总线只投影，不推断：设备状态只能来自 MCP 工具显式 `structuredContent.deviceStatus`。
- `device_status.state` 是领域无关的 JSON 对象；内核不解释 `probe/serial/cpu/backend`。
- SSE 仅绑定本地服务；`sessionId` 必须经过现有 ID 校验，防路径穿越。
- 跟随默认 200ms 轮询，不使用 `fs.watch`；延迟上限约 250ms。
- 本轮不实现 Web 审批 API/UI，不新增 `approval_request` 产生者。
- 本轮不新增独立 `evidence` 事件；evidence 由 `tool_result.payload` 承载。
- `mcp_status` 写失败按观测性降级（stderr/`statusWriteFailure`），不中止会话；`tool_started`/`device_status` 写失败按会话错误处理。
- 未授权不提交：每任务以测试/typecheck 为完成门禁；commit 需用户明确授权。
- 每个任务完成后执行两轮独立 review：第一轮实现审查并修复；第二轮独立复核/红队通过后才进入下一任务。
- 覆盖率阈值沿用 `npm run coverage` 的 lines ≥ 85%。

## Review Focus

1. 活跃会话首次打开时读到尾部半行，SSE 不得误报 `session_corrupt`——Task 2 覆盖 open 尾部半行、closed 半行报错。
2. 长断线补播不能再次触发 500 条实时队列溢出，否则 `lastSeq` 重连活锁——Task 3 覆盖大补播和实时溢出分离。
3. 客户端重连/切换会话的 `seq` 去重、缺口重拉、旧流串台——Task 6 覆盖。
4. 设备状态被推断、patch 语义错误、页面重载无法重建——Task 4/6 覆盖显式发布、缺字段保留、切换归零、重载折叠。
5. 新增事件类型遗漏 `persistence`/`buildMessages`/转写投影导致下一轮或回放失败；MCP 旧 `status` 迁移丢事件——Task 1/5 覆盖。

- [ ] **Step 1: 写失败测试 `tests/events-log-tail.test.ts`**

用临时会话目录与 `createSession`/`handle.append`，覆盖：

- `read(id, -1)` 返回全部事件并带 `sessionId`；`read(id, 1)` 只返回 `seq > 1`。
- `since` 为 -1/0/最后 seq 的行为；非法 ID 抛 `SessionNotFoundError`（不暴露路径）。
- 活跃会话：向 JSONL 追加半行（无换行）后 `read` 成功返回已完整事件，不抛 `SessionCorruptionError`；补全该行后 `follow` 收到该事件。
- **交接窗口**：先 `read`，再追加一条事件，然后启动 `follow(since=readLastSeq)`；`follow` 必须先发出该事件，不得从文件末尾直接开始。
- **pendingTail**：半行存在时启动 `follow`，补全后事件只出现一次，不漏不重；`snapshot.generations` 的 offset 指向最后一个完整行末尾，`pendingTail.offset` 指向半行起始字节。
- closed 会话：尾部 JSON 不完整 → `read` 抛 `SessionCorruptionError`；尾部无换行但完整 JSON → 按完整事件返回。
- `follow` 在 `handle.append` 后 ≤3 个轮询周期内产出事件；`handle.close()` 后迭代自然结束。
- 分代：构造 `session.v1.jsonl` + `session.v2.jsonl`（seq 连续）后 `read` 合并；`v2` seq 不连续 → 抛错。
- 截断：记录 offset 后把当前代文件缩短并写入新内容，`follow` 从 0 重扫、按 seq 去重，不因重复报错。
- 中文多字节：把一个含中文 payload 的事件字节流按中间位置拆成两个 Buffer 喂给行解析器，结果无替换字符、无损坏误判。
- 路径安全：symlink/junction 指向 session 目录外部时拒绝（若平台不支持 junction 则 skip）。
- 完整行 JSON 损坏 → 抛 `SessionCorruptionError`。
- abort signal 后 `follow` 在下一个轮询周期内停止。

- [ ] **Step 3: 实现解析与查询落盘**

- `parseDeviceStatus`：只接受普通对象（非 null/数组）；UTF-8 JSON ≤8192 字节；递归深度 ≤4；返回原对象引用或克隆（不执行任何方法）。
