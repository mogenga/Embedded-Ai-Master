**Review 结论**

- 第一轮 builder check 提出 7 个问题，均已写入 spec：`BatchOptions.permission` 缺省语义、审计 `callId`、并发审计失败、`paramsKeys` 来源、审批串行、`ruleIndex` 基准、配置加载时机。
- 第二轮独立 reviewer 发现 2 个 blocker + 8 个 major，已修复：
  - `src/context/build.ts` 对未知事件默认抛错，`permission_decision` 会让下一轮投影、resume、fork 失败；已加入忽略分支并要求测试。
  - 默认 `diagnose` 会使既有 `integration.test.ts` 的 shell / MCP 控制工具用例失败；plan 增加“显式切到 danger-full-access”的迁移步骤，不为过测试放宽默认。
  - inline 配置改走与文件相同的 strict Zod；`RunOptions.permissions` 外层未知键拒绝。
  - 规则求值与 `tool.access` 异常一律 deny；destructive/readOnly 冲突注解归 unknown。
  - 审批超时改用 `setTimeout` + `AbortController`，保证 fake timers 可测。
  - resume 权限配置加载前移到 `resumeSession` 之前，避免 crash recovery 已改日志后才失败。
  - 补齐 MCP `source.call`、前端新事件 fixture、shell 默认 deny、`onDecision` 恰好一次等测试。

**被拒绝或纠偏的内容**

- 未采用“项目级配置默认加载”：不可信仓库可自行提权。
- 未采用 JSONPath/表达式引擎：引入依赖与执行语义，超出阶段 1。
- 未把 Web 审批 API 纳入本轮 plan：按 m2-roadmap 留到阶段 2。
