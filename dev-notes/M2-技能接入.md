## 2026-10-22 · 第一段：分期与实现

**用户关键原话**

- 「接入skills功能，发子代理」

**关键产出**

- 任务拆分（4 条并行，互不碰同一文件）：
  - **A 内核存储** —— 新增 `src/skills/store.ts` + `src/skills/types.ts`。纯存储层：读、写、删，不含斜杠命令逻辑。
  - **B 宿主接线** —— `desktop/host/host.js` 新增 `getSkills` / `saveSkill` / `removeSkill`；`init` 与 `listCommands` 追加技能行；`skills` 宿主事件。
  - **C 渲染层** —— `desktop/renderer/commands.js` 的 `mergeCommands` 认 `source: "skill"`；新增纯函数 `expandSkill(skill, args)`；`desktop/renderer/app.js` 的 `submit()` 走展开路径；`desktop/renderer/settings.js` 恢复「技能」页。
  - **D 文档** —— `docs/deferred-issues.md`、`desktop/MATRIX.md`、`README.md`、本文件。
- **存储格式**（两个作用域，同名时项目覆盖用户）：
  - 用户级：`$HARNESS_HOME/skills/<name>.md`
  - 项目级：`<workdir>/.harness/skills/<name>.md`
  - 文件＝可选 frontmatter（只认 `description` / `argument-hint`）＋ 正文。**没有 frontmatter 也是合法技能**，整份文件就是正文；frontmatter 未闭合报 problem 并跳过该文件，不影响同目录其它技能。
  - 名称 `/^[a-z][a-z0-9_-]{0,63}$/`，且不得与内置命令 `clear` / `context` / `compact` 同名。
  - 写入走「临时文件 + fsync + rename」，UTF-8 无 BOM、LF、末尾换行。
- **两个值得记住的设计决策**：
  1. **技能名不得与内置命令同名。** 渲染层的 `/` 面板按名字合并，内置动词优先，同名技能永远轮不到执行——不是「可能不生效」，是**必然不生效**。所以在读取时就把这类文件报成 problem 并跳过（而不是让它静静躺在列表里点不动），保存时也直接拒绝。仓库的 `BUILTIN_COMMAND_NAMES` 由内核导出、宿主共用，避免两处各写一份字面量。
  2. **转录回显用户敲的那行，不回显展开后的正文。** `/review src/uart.c` 在气泡里就是这一行；展开后的提示词作为普通 `user` 事件落盘，回放与导出都能读到。理由：展开文已经进了会话事实源，转录里再印一遍会让同一段话出现两次；而用户需要对上的是自己的动作（「我敲了 `/review`」），不是「模型看到了什么」。代价是转录里看不到 `$ARGUMENTS` 究竟替换成了什么。

**被拒绝或纠偏的内容**

- **没有加模型可调用的 `Skill` 工具。** 本轮刻意不做：用户要的是「技能」这个功能，不是「让模型自己挑技能」。内核工具集里至今没有 `Skill`（`grep -rn skill src/tools/` 为空），模型看不到技能清单，唯一入口是用户敲 `/name`。这不是遗漏，是范围决定；触发条件（什么时候该做）写在 `docs/deferred-issues.md` D-198 第 2 条。
- **没有给项目作用域技能加信任提示。** MCP 的项目配置要 `trustProjectConfig` 才读，技能不设同样的门。理由：门控该跟着**执行**走——`mcp.json` 会拉起进程，项目技能只是惰性文本，读取不执行任何东西，展开后劝说的工具仍逐个过权限门。给纯文本加一道比读工作区文件更严的门，换不来执行面上的任何安全。**但同名覆盖留了缺口**：项目技能会静默覆盖同名的用户技能，而命令面板不显示作用域，用户在敲命令的那一刻恰好看不出来。这条按缺口登记（D-198 第 4 条），并给了修法建议（同名时用户作用域优先）。
- **没有把 `$ARGUMENTS` 展开放进内核。** 展开放进内核，「保存一段提示词」就会变成「运行一段脚本」——内核不认识 `$ARGUMENTS`，也不执行技能正文里的任何东西。这一条写在 `src/skills/types.ts` 的头注释里，防止后来者顺手挪进去。

**翻车与返工**

- **本节由文档子代理写就，它按分工要求没有运行测试套件**（当时测试文件正被其它并行任务修改）。实跑结果由主控在「第二段」补齐：`npx vitest run` 全量 2321 passed | 4 skipped，`npx tsc --noEmit` 与 `npm run build` 均退出码 0。
- **已复现的缺陷（当段未修，第二段已修；D-198）**：技能名允许下划线（`SKILL_NAME_PATTERN` 为 `/^[a-z][a-z0-9_-]{0,63}$/`），但 `desktop/renderer/commands.js` 解析斜杠命令的 `SLASH` 是 `/^\/([a-z][a-z0-9-]*)(?:\s+([\s\S]*))?$/i`，字符类里没有 `_`。实测（直接 import 该模块，不跑测试套件）：`parseSlashText("/review_diff foo")` → `null`，`parseSlashText("/review-diff foo")` → `{name:"review-diff",args:"foo"}`；而命令面板的调用点正则 `/(^|\n)\/([a-z0-9][a-z0-9-_]*)?$/i` 含 `_`，所以面板会打开、会列出这个技能、点选还会把 `/review_diff ` 插进输入框。结果是**回车后整行被当普通提示词原样发给模型**：不展开、不报错、没有任何提示。这与 R3 同类（界面承诺了一件不会发生的事），而且失败方式是让模型读到一句它不认识的 `/review_diff`。
  - 根因不是打错一个字符，是**「能存在的名字」与「能敲出来的名字」由两份独立正则描述**。补的不变量应是：`SKILL_NAME_PATTERN` 接受的每个名字，`parseSlashText("/" + name)` 都必须解析回该名字。
  - 建议修法：给 `SLASH` 字符类补 `_`，并把 `tests/desktop/commands.test.js` 里「`/foo_bar` 按散文处理」那条断言改成正例。曾考虑反过来收窄名字规则，但界面文案与 README 都已写下划线，且下划线在斜杠命令里不含额外表达力——收窄只会让已建的文件失效。
- **第二处已复现的缺陷（当段未修，第二段已修；D-198）**：技能的保存/删除失败提示，用户在设置页看不到。链路是宿主只发一条 `notice{warn}`（失败不广播 `skills`，这部分是对的），而 `app.js` 把 `notice` 一律写进**转录**；设置页却是 `showModal()` 的 `<dialog>` + 遮罩，转录在它后面，`settings.js` 的 `handleEvent` 又没有 `notice` 分支。再加上表单在发命令后无条件 `form.remove()`，用户的实际体验是：点保存 → 表单消失 → 列表没变 → 没有任何提示，草稿也没了。这与 R3（失败必须显式可见）直接冲突。修法记在 D-198：设置页处理 `notice` 并在页内显示；保存失败时不关表单。
- **其余两处是集成过程中的正常接缝，已在渲染层落地时解决（不是缺陷）**：
  - `settings.js` 里 `buildSkillsPage()` 早已写好但没进 `settingsPages()`，恢复时同时补了列表项与数据来源；数据直接来自 `init` 的 `skills` 事件，`settings.js` 的 `handleEvent` 也已带 `skills` 分支。（**第二段已改**：技能页现在打开即发 `getSkills`——技能是手工可编辑的文件，开机快照描述的是一个没人重读过的目录，与知识库页同一理由。）
  - 命令面板与 `submit()` 都消费 `state.skills`，而设置页保留自己的一份副本：技能是全局的、不属于任何会话，`session_loaded` 不清它。两处各持一份而不是共享同一个可变数组，是为了不让两个模块通过一个谁都不拥有的列表耦合。
