### 需要我判断的三处（Task 1 提出）

1. **`trackFillOpacity` 的参数**：计划表里我写的是 `position`，正文改成 `g` 并在
   派发消息里说明。子代理按 `g` 实现，并论证 brief 表格里的原签名是错的（轨道上
   有两个独立弹簧量，位置和 Galaxy 强度不同步）。**采纳**，理由成立。
2. **`foldVisibleCount` 的 2/4/6/8/12/16 口径**：只有「层 4、层 5 各贡献 4 条」时
   这六个数才对得上，即每条 path 左右各实例化一次。子代理把推导写进了报告 §3，
   我核过：`2 + 2+2+2+4+4 = 16`。**采纳**，并给 Task 3 加了一条约束：主沟必须
   保持单条 path 三个子路径，不许拆。
3. **`trackFillStops` 与 spec 「Low 到 Medium 使用第一组」的措辞冲突**：子代理指出
   按公式 `t = position - 1`，position=2（Medium）用的是第二组，不是第一组。
   **已解决（2026-11-09，我核的）**：那句话说的是**区间端点**，不是档位本身。
   实测六档的五个色标（`trackFillStops` 直接跑）：

   ```
   position 1 -> #312a2d #56394c #7d4970 #a15992 #af5e9d   ← 第一组，blend=0
   position 2 -> #312a2d #51374c #70456b #8f538b #995796   ← 第二组，blend=0
   position 4 -> #312a2d #4d384a #66436f #765499 #7c5aa7   ← 第四组，blend=0
   ```

   position=1 恰好落在第一组上（`blend = 0`），position=4 恰好落在第四组上——
   「Low 到 Medium 用第一组」「Max 到 Galaxy 用第四组」两个区间说法都成立。
   决定性证据：spec 自己给的抽查点「Max 中段约 `#66436f`、90% 处约 `#765499`、
   最前缘约 `#7c5aa7`」与 position=4 的**逐位吻合**。公式读对了，无需改。

## 2026-11-09 · 任务栏图标（并行的第二个问题）

用户报告「任务栏图标仍然是 electron 的图标」。我先自己测了一轮，得到的事实：

| 事实 | 怎么测的 |
|---|---|
| 窗口图标**是对的**（蓝色 EM），开发与安装形态都对 | `WM_GETICON` 取 `ICON_BIG` |
| exe 资源里的图标**是对的** | `PrivateExtractIcons` index 0 |
| 任务栏按钮显示的是**原子标志** | `PrintWindow(Shell_TrayWnd)` 抓图放大 |
| 开始菜单快捷方式 AUMID = `com.embedded-ai.master` | `SHGetPropertyStoreFromParsingName` 读 `PKEY_AppUserModel_ID` |
| 运行时 AUMID = `com.embedded-ai.master`（`main.js:708`） | 源码 |
| `package.json` 的 `appId` = `com.embedded-ai-master.app`（**不同**） | 源码 |

剩下的是因果链，派了一个诊断子代理去查（报告 `.superpowers/sdd/icon-diagnosis-report.md`）。
**我没有等结论就先改了**——这点记在这里：图标问题的修复方案要等诊断报告，不要凭
「窗口图标是对的」就宣布修好。
