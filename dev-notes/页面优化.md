**设计判断（brief 留白处，由实现者拍板）**
- **`baseUrl` 的覆盖规则**：brief 写的是「冲突时不要覆盖用户已手填的非空值？」。这里定为「空着，或正好等于某个预设地址时才替换」。只判空会让「DeepSeek → Kimi」连着换时卡在 DeepSeek 的地址上；只判「非空就不动」又会让手填地址被冲掉。判据是「这个地址是不是我们自己填进去的」。

**设计判断（brief 留白处，由实现者拍板）**
- **显示名称与厂商归属都存 localStorage**：内核 `ProviderConfigSchema` 会 strip 未知键，写进 `providers.json` 等于放进一个会被静默删掉的字段。键用 `prometheus.providerMeta`，按服务名索引。
- **厂商归属是卡片自己的状态，不再从服务名反查**：同厂商多张卡时名字不再等于厂商 id，反查立刻失效；且「用户明确选了自定义」必须能与「没存过」区分（存 `null` vs 不存）。
- **服务名后缀而非 `deepseek-home` 这类语义名**：显示名称才是人看的标签，服务名只需唯一；`deepseek-2` 也保持了「名字前缀 = 你在文件里找这条服务」的可预测性。手写的名字换厂商时不动（`isAutoProviderName`），避免一次「换厂商」把用户自己的命名冲掉。
- **面板一行 = 一个服务，不按厂商合并**：两个 Key 的模型清单与凭据不同，按厂商合并会隐藏「这个模型用的是哪个 Key」，而这正是用户提的第二条需求。
- **右栏表头显示名称、服务名进 `title`**：屏幕上人看的是标签，`service/model` 引用仍可查。
- **标签写在本机、不等宿主回包**：写入失败时页面明说「服务已保存、显示名称没存下」；宿主拒绝保存时多出的标签是孤儿，`provider-meta.js` 只按文件里的名字查，孤儿不显示，下一次保存整份重写清掉。
- **左栏标签允许两行**：实测「DeepSeek 公司账号 / DeepSeek 家里备用密钥」在 108px、136px、150px 单行下都被截断，而截掉的正是区分两个 Key 的尾部；改为两行 + `overflow-wrap: anywhere` 后两个宽度、两套主题下 `scrollWidth <= clientWidth`。

**被拒绝或纠偏的内容**
- 否掉「把 `displayName` / `vendor` 写进 `providers.json`」：需要改内核 schema，brief 明令不改。

**占用环为什么不渲染**
`<circle id="context-ring">` 的 `stroke-dasharray` 只在 `applyContext()` 里设置，首次绘制时**没有** dash array——而 SVG 里未声明 dash array 的圆会画成**一整圈实线**。所以从第一帧到第一次测量之间，环是满的，看起来像「已用 100%」。这不是「没渲染」，是**渲染了一个假读数**（R3）。修法：在 CSS 里声明 `stroke-dasharray: 37.7; stroke-dashoffset: 37.7;`，与 JS 常量 `2π×6` 同值，让 SVG 自带默认就是空环。

## 2026-11-05 · 第七轮：厂商切换关闭面板（上一轮的修法无效）

**用户原话**
- 「选择厂商后面板不再收起的问题没有解决」
- 「查一下。」

**上一轮修法为什么没生效**
我上一轮让 document 的关闭判断把 `#model-menu` 也算作「内部」。**这个判断在自己的重渲染之后才执行，而那时被点的节点已经不是 `#model-menu` 的后代了。**

链条：
1. 点厂商栏某一行 → 该行的 click handler 调 `selectModelRailProvider()`。
2. 里面 `renderModelMenu()` → `modelMenu.innerHTML = ""` → 被点的那个 `<button>` **从文档中摘除**。
3. 事件继续冒泡到 `document` 的关闭处理器。
4. `event.target.closest("#model-menu")` 对一个**已分离**的节点返回 `null`。

所以条件恒为「点击在外面」，面板照样关。上一轮的改动只是让这个错误条件更难看出。

**正确的修法**
在**捕获阶段**记录落点——那时任何 handler 都还没改 DOM：

```js
let modelMenuClickInside = false;
document.addEventListener("click", (event) => {
  modelMenuClickInside = Boolean(
    event.target?.closest?.("#model-menu") || event.target?.closest?.(".model-control"),
  );
}, true);
```

冒泡阶段的关闭处理器先看这个快照，再看几何（兜底合成事件）。捕获阶段由 DOM 规范保证先于目标与冒泡阶段，所以这个快照描述的是「用户点到的是哪块 DOM」。

**同一 bug 的第二个受害者**
模型面板底部的「刷新模型列表」按钮同样会重渲染面板，也同样会在点击后把面板关掉——它一直没有被发现，因为用户很少点。两处一并修好。

**没有同样问题的菜单**：模式菜单与推理档菜单选中后主动 `setModeMenu(false)` / `setEffortMenu(false)`，且选项点击不重建菜单。只有模型面板会在点击时重建自己。

**测试与验证**（隔离 `HARNESS_HOME` + `--user-data-dir`，端口 9350，三个假 provider）
- 点第二个厂商 → 面板仍开、右栏切到 `km`、只列 `km/m2`。
- `ArrowRight` → `km → gl`，面板仍开、焦点仍在厂商栏。
- 点面板外 → 面板关闭（回归未被破坏）。
- 点「刷新模型列表」→ 面板仍开并显示加载中。
- `check:js` 38 文件通过；`tests/desktop` 536 passed / 3 skipped。

**教训**：判断「点击落在哪个元素」时，如果被判断的 DOM 可能在同一事件里被重建，就必须在捕获阶段取样或改用 `pointerdown`。冒泡阶段读 `event.target` 的祖先链，前提是那棵树还活着——而这个前提在「点击导致重渲染」的控件上必然不成立。

- 净 −101 行。提交 `d73971a`。

**翻车：精确匹配怎么都失败**
Edit 工具连续三次报「String to replace not found」，看起来像我把文本抄错了。用 `od -c` 才看见：那段代码里藏了**三个真实的 0x08（退格）字节**——源码想写 `\b` 词边界，存进文件的是字面控制字符。普通编辑器、grep、文件比较全都显示成 `\b`，肉眼无法分辨。

最终改用锚点切片脚本（`indexOf` 找函数头尾，切出来的片段必须同时含两个函数名才允许写入），绕开字节比对。

**顺带发现的真相：这个功能从写进去起就是死的**
把两种写法放在真实串上测：

```
源码想写      /\btest/        ← 词边界断言
实际存进去    /<0x08>test/    ← 字面退格字符

测试串 "I ran the tests and they passed."
  字面退格版  → false   永不匹配
  词边界版    → true    正确匹配
```

三条分支（`test` / `error|fail` / `implemented|added|changed`）**全部是字面控制字符**，所以 `next` 恒为空，`suggestNextTurn()` 每次都在 `if (!next)` 里 `hidden = true` 返回。用户从未见过任何建议；设置里那个开关控制的是一个不可能触发的行为。

**为什么没人发现**
这个功能**没有任何测试**。`check:js` 只做 `node --check`，语法正确即通过——控制字符在语法上完全合法。三个字节因此潜伏至今，跨过了多轮重构。

**这次是怎么被挖出来的**
不是靠看代码，是靠「删除时精确匹配失败」这个异常。如果它没被删，可能还会再潜伏很久。

**教训（针对将来重建类似功能）**
1. **`\b` 这类反斜杠转义在 Windows + CRLF + 各类编辑器的组合下有被误伤成控制字符的风险**。要么用 `includes` + 显式分隔判断，要么在写入后立刻用测试锁住行为，而不是只锁语法。
2. **一个永不触发的分支和一个「恰好没触发」的分支，在代码审查里长得一样。** 判断依据只能是测试或运行时观测——这次两样都没有。
3. **`check:js` 的覆盖面要说清楚**：它挡语法错误，不挡语义错误，也不挡不可见字符。把它当静态检查的证据是过度解读（与 D-006 的教训同类）。
4. 删除既有功能时，**先量它的实际行为再决定它是否「在用」**。这次如果先问「有多少用户见过这个建议」，会发现答案可能是零，删除的决定会更早做出来。

- 全仓库扫描 `js / mjs / cjs / ts / html / css / json / md` 的非打印控制字符：无其它命中。
- `git show HEAD:desktop/renderer/app.js | grep -c $'\x08'` → 0（随函数一起删掉了，不需要单独修）。
- `summariseLastAssistant()` **保留**：它还有第二个调用方 `notifyIfAway(t.notifyTurnDone, …)`（离开窗口时的系统通知）。
