## 关键产出

### 5.1 Datasheet 三处静默截断（OPT-22）

`mcp-servers/datasheet/` 新增三个字段，沿用 `kb` 的 `truncated` / `scanTruncated` 二分：

| 字段 | 语义 |
|---|---|
| `count` | `limit` 裁剪前的命中总数，可以大于 `hits.length` |
| `truncated` | `hits` 被 `limit` 截断 |
| `scanTruncated` | 文件遍历被截停（200 文件预算**或** 6 层深度上限） |

三处缺口逐一补上：`search()` 接收 `walkPdfFiles().truncated`、`hits.slice()` 旁补 `count`/`truncated`、`walkPdfFiles()` 的 `depth > maxDepth` 分支置位（原来直接 return）。

早退路径（空查询 / 提取器缺失 / token 零命中）全部补齐字段。既有的诚实行为逐字未改：`skipped[]` 三条 reason、零命中拒答逻辑。

测试 94 → 102。RED 三次（深度不置位、count 不披露、search 丢弃遍历截断）各报红后恢复。

**判断**：`scanTruncated` **拓宽了语义**（原来只表示预算截停，现在深度截停也算），没有新增 `depthTruncated`。理由是对调用方是同一件事（结果可能不完整），与 kb 的用词保持一致。代价是无法区分两种成因，已写进 `docs/operations/datasheet-mcp.md` 的对照表。

### 5.2 `system_prompt_mismatch` 人话（D-221 ②）

`desktop/host/host.js` 新增 `systemPromptMismatchHint()`：

> 发送失败：这个会话没有记录系统提示词，续聊时不能补写。请新建会话，或清空 `<HARNESS_HOME>/run.json` 里的 systemPrompt 后重试。

**推翻了 brief 的前提**：brief 假设「宿主识别错误码」，但 `src/server/runner.ts` 会把就绪前的所有失败重新包装成 `RunnerError("model_unavailable", "会话启动失败: <原文>")`（`tests/server/runner.test.ts:479` 钉住了这个契约）。所以 `error.code` 恒为 `model_unavailable`，只能靠消息文本区分。

选的是**更窄的那句**（`Cannot add a system prompt to a non-empty session without a system event`），不是整个错误码——同一个码还覆盖「有 system 事件但与当前值不符」，那时说「没有记录提示词」就是假话（R3）。

内核规则未动。测试 2 例（两种形状：一条得到中文副本，另一条保持英文原文且不含新措辞）。

### 5.3 设置页草稿守卫（OPT-39）

`desktop/renderer/settings.js` 新增 `requestClose()`，三条关闭路径共用：Esc、背景点击、侧栏返回。`connectionDirty` 为假 → 直接关闭**不弹确认**；为真 → 走既有 `confirmAction`。

> [!WARNING]
> **最大的发现不是草稿，是确认框根本看不见。**
> `confirmAction` 原来建的是 `z-index: 200` 的 `<div>`，而设置页与快捷键面板是 `showModal()`（浏览器顶层图层）。在真实 Electron 44 里做命中测试：确认框 OK 按钮位置 `elementFromPoint` 返回 `settings-dialog`，`focus()` 也拿不到焦点（`focusTook: false`）。
> 也就是说设置页里删除权限规则 / MCP server / 技能 / 记忆 / 工具链包的二次确认，**用户从未看见过**。这不是 OPT-39 描述的问题，也不是本次引入的，但若照搬「复用 confirmAction」，新守卫会是第二个看不见的框。

改为模态 `<dialog>`（`showModal()` + `cancel` 兜底 + `close()` 后再 `remove()`），CSS 跟着改。

第二处实测：模态 dialog 打开时，背景点击被重定向到 dialog 自身（`dialog-target:settings-dialog`），`#modal-scrim` 的监听 0 次触发。所以「遮罩点击」必须在 dialog 上监听、用 `event.target === settingsDialog` 判断。

**真实窗口里发现的 bug（源码测试当时是绿的）**：有草稿时按 Esc，事件序列是 `showModal:confirm-overlay → cancel:confirm-overlay → cancel:settings-dialog`——同一次按键既打开了确认框又被它吃掉，然后原生关闭了设置页，而 `hidden` 仍读 `false`。修法：Esc 分支加 `event.preventDefault()`，并在设置页 dialog 上加拒绝 `cancel` 的监听，让 `hidden` 保持单一事实源。

### 5.4 `@` 搜索两条限制（D-184）

**① 目录进结果——实现**。关键论证推翻了 D-184 的悲观前提：目录在 `walkFiles` 里本来就已发现（`entry.isDirectory()` 时才入队），报告它**不增加任何 I/O**；`scanned` 仍是文件数，所以同一个预算买到的文件覆盖不随目录密度变化——这与 `glob`/`grep` 的语义一致。

`walkFiles` 新增第 6 个可选参数 `visitDirectory(absolute, relative)`，在目录通过接受规则（非符号链接、不在忽略清单）**入队时**触发。`FileNameMatch` 新增 `kind: "file" | "dir"`。

**② 旧 `dist/` 状态按需可见——不做常驻横幅**。确认过 `searchUnavailableWarned` 与静默空 `file_matches` 仍在。保留「每进程一条 notice」（每按键一条会埋掉转录），但**每条 `file_matches` 都带 `unavailable: true`**，弹窗就地显示原因与两种修法（源码形态 `npm run build`，安装形态重装）。

**顺带修的交互**：弹窗只有说明、没有可选项时，keydown 不再吞掉 Enter/Tab。

**主代理补充的 `kind` 透传**：内核产出 `kind` 但宿主 `files.map(f => f.path)` 把它丢掉了，成了死字段（D-196 那一类）。改为发 `{path, kind?}`，渲染层给目录行画尾随 `/`。RED 验证：注入 `false ? …` 后断言报红，恢复后 6 例全绿。

## 被拒绝或纠偏的内容

- **5.1 没有拆 `depthTruncated`**：同名覆盖两种成因，靠描述说明。拆字段会让下游各写一份判断。
- **5.2 没有按错误码映射**：runner 把码压平成 `model_unavailable`，按码映射会连带命中「提示词不一致」那种形状，说成「没有记录」就是假话。
- **5.3 没有新造确认框**：沿用 `confirmAction`，但先把它从不可见的 `<div>` 修成模态 dialog。
- **5.3 没有在无草稿时也弹确认**：那是警告一件不会发生的事。
- **5.4 没有改预算计量单位**：D-184 原文担心「目录计入会让截断语义变模糊」，解法是不改变单位，而不是把目录也算进去。
- **5.4 没有做常驻横幅**：弹窗是用户每次敲 `@` 都在看的表面，按需可见即可。
- **5.5 删了 `recovery`**：任务只点名三项，但它是同一套功能的第四块，留着就是半成品。
- **5.6 没有为「三项都算完成」去硬凑**：①② 的宿主侧本就正确，如实报告「缺口在渲染层」而不是伪造修复。

## 翻车与返工

- **主代理的失误（最重要）**：两个子代理把批次 5 的记录追加进了 `dev-notes/页面优化.md`（不属于那一轮）。主代理尝试挪走时，用 Python 先截断了源文件、随后写临时文件失败；接着用 `git checkout --` 还原——而该文件从未暂存，**两段原稿丢失**。本节因此是重建的。教训：**对被修改但未暂存的文件，任何「先写后判」的脚本都必须先备份**；`git checkout --` 在没有备份的前提下不是「撤销」，是「销毁」。
- **5.3 的两个假信号**：源码测试全绿，但真实窗口里 Esc 会连关两层（`cancel` 事件链）。另有一次 13 项回滚里 2 项仍绿——`bodyOf()` 切块越界与符号扫描漏文件，测试自身有 bug。
- **5.6③ 的 RED 表现为超时而非断言失败**：宿主丢弃 `atSeq` 时分叉反而成功，用例等的 notice 永不到来；超时本身就是证据。
- **子代理交叉**：两次 `npm run verify` 中看到了对方尚未落地文件的失败（`settings-draft-guard` / `fork-atseq`），对方完成后转绿。并发派发时需要提醒「别把别人的中间态当自己的回归」。
