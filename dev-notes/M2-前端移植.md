> 阶段：前端替换。起止：2026-10-20。

## 用户关键原话

- 「不走 Superpowers，直接推」——本轮不走 superpowers 的 spec/plan 流程，按 AGENTS.md 的约束直接推进。
- 早前问询「现在重构前端页面会与阶段 4 任务撞线吗」——本移植把阶段 4 依赖的 `src/ui` 一并替换掉，等于先行清场。

## 背景与结论

`prometheus-frontend/` 是 Electron 桌面前端（renderer 5848 行、host 3444 行），协议是 NDJSON over stdio，与当前内核的 HTTP/SSE + 会话日志模型不同。本轮按用户选择：**双形态**（Electron 桌面 + 浏览器）、**直接替换**旧 Preact 工作台、**隐藏未支持项**而不伪造、代码放 `desktop/`、设置页只保留 UI 偏好、Electron 由用户安装。

## 被拒绝或纠偏的内容

- **不引入 Vite / Preact**：目标前端是纯 ES 模块、无构建步骤；`build:web` / `dev:web` / `test:ui` / `typecheck:web` / `verify:ui` 全部删除而不是保留空壳。
- **不伪造未支持能力**：git/PR/终端/worktree/packs/browser/skills/… 的入口从 DOM 里隐藏（保留节点、`hidden` 属性），宿主与 bridge 对这些命令回显式 `notice`（R3）。
- **不保留「始终允许」**：内核审批桥只有单次 allow/deny，持久规则不存在，按钮不渲染（渲染出来就是会失信的承诺）。
- **不伪装上下文占用率**：内核只给花费不给占用，百分比隐藏而不是编一个（D-165）。
- **不把阶段 4 的回放/导出/设备控制顺手做掉**：那三节原设计基于已删除的 `src/ui`，本轮只登记为待重写（D-166）。

## 翻车与返工

1. **Windows 动态导入路径**：`import(path.join(...))` 把 `E:\...` 当成协议名 `e:`，宿主启动即 fatal。改用 `pathToFileURL(...).href`。
2. **`createRunner` 未定义**：重构时把构造逻辑抽成函数却忘了加定义，`init` 直接抛 `createRunner is not defined`。补上后握手恢复。
3. **bridge 的 `session_loaded` 抹掉了用户消息**：`prompt` 成功后发 `session_loaded{messages:[]}`，渲染层按它重建转录，把提交时已画出的用户气泡清空（浏览器实测 `userTurns: 0`）。改为：只有切换会话才重建转录，新建会话只发 `state`。
4. **`adoptSession` 冲掉 running 标志**：`ctx` 被重建后 `running` 归零，`stream_end` 不再补 `run_end`，一轮永远处于忙碌。恢复标志后收尾正常。
5. **会话侧栏不展开**：`state.cwd` 为空时分组键对不上，已打开会话的项目折叠。改为从会话列表里取当前会话的 `workdir` 作为 `cwd`。
6. **侧栏标题为空**：内核 header 没有 title 字段，列表接口也不给标题。改为读首条 user 事件并缓存（上限扫 30 条，避免大 home 卡顿）。
7. **`always` 按钮被重新显示**：渲染层 `permission_request` 分支会把所有 `[data-permission]` 按钮设为可见，覆盖了 HTML 里的 `hidden`。改为只显示 `yes`/`no`。
8. **KB 回归用例在并发下超时**：并行跑满 worker 时单次检索可达数秒，5s 默认超时误报。给三个检索用例单独 30s 超时；单跑与两 worker 均全绿。
9. **测试用假网关 400 而非拒连**：拒连会触发 5 次指数退避（约 27s），用例超时。改用本地 HTTP 400 网关，失败立即返回。
10. **favicon 404**：静态根没有 favicon，浏览器控制台报错。加 `data:` 内联图标。

## D-164 修复：token 级流式（2026-10-20 第二轮）

用户要求：「D-164 无 token 流式进行修复」。

### 做了什么

1. **模型适配层支持流式**（`src/model/openai.ts`）
   - 请求体默认 `stream:true` + `stream_options.include_usage`。
   - 按 SSE 帧解析 `delta.content` 与 `delta.tool_calls`（参数分片累积，id/name/arguments 分别拼）。
   - 响应形态三态判定：`Content-Type: text/event-stream` → 流式；首行是 `data:` → 流式（兼容漏发响应头的网关）；否则一次性 JSON。
   - 网关用 400/404/405/415/422 拒绝流式时，降级为一次性响应并在**该 provider 实例**内记住结论，不再试探。
   - 已经把增量交给上层之后不再重试（重试会把同一段文字再送一遍）。
2. **内核落盘增量**（`src/loop/assistant-delta.ts` + `src/loop/query.ts`）
   - 新增 `assistant_delta` 事件（`{text}`），按批落盘：默认 60ms 或 400 字符。
   - `assistant` 事件仍承载这一轮的完整内容；投影层（`buildMessages`）忽略 delta，只用 `assistant` 重建模型上下文。
   - 写失败被吞掉并计入 `dropped`：同一轮的完整内容在 `assistant` 事件里，增量只是提前显示。
3. **协议层与前端**（`desktop/renderer/protocol.js`）
   - `assistant_delta` → 渲染器 `assistant_delta`。
   - 完整 `assistant` 事件只补齐**尚未流式过**的部分（用 `ctx.streamedText` 比对），不重复已显示的文本。

### 翻车与返工

1. **流式 tool_calls 的 wire 形状不对**：累积出来的对象缺 `type`/`function` 包装，被 `parseToolCalls` 判成「malformed tool call」。改成累积后还原成 OpenAI wire 形状，走同一套解析规则。
2. **降级缓存放在模块级**：一个网关的结论会污染另一个（并发跑不同 baseUrl 的测试会串），且让测试依赖执行顺序。改成 provider 实例级状态。
3. **JSON 路径会丢首块字节**：形态判定可能要等到第二个 chunk 才出结果，第一块被 `jsonChunks.push` 之外丢弃。改为原始字节始终保留。
4. **形态判定函数太脆**：只看第一行，遇到 SSE 的 `event:` 行或注释行会误判成 JSON。改为多行扫描并跳过 `:` 开头的注释。
5. **测试断言写错**：「降级后不再试探」用例期望 1 次一次性请求，实际是 2 次（两次 complete 各一次）。行为是对的，断言改对。
6. **`dropped` 按字节还是字符**：实测「丢失」是 2 个字符，断言写成 3。断言改对，并注明按字符计。

### 验证

- `npm test`：73 files / **1888 passed / 1 skipped**（skip 为需 `HARNESS_COMPAT_LIVE=1` 的 live 用例）。
- `npm run typecheck` / `build` / `build:mcp` / `test:mcp`（219）全 exit 0；`coverage` lines 93.23%。
- 新增测试：`tests/openai.test.ts`（流式 9 例：逐帧 delta、流式 usage、流式 tool_calls、漏发 Content-Type、网关拒绝降级、降级后不重复试探、非法帧、缺 choices、`stream:false`）、`tests/assistant-delta.test.ts`（5 例）、`tests/events-producers.test.ts`（增量落盘 4 例）、`tests/desktop/protocol.test.js`（增量映射 4 例）。
- 浏览器实测（无头 Chromium + 本地 SSE 网关）：回答**逐段出现**（采样长度 1 → 4 → 5 → 8 字符），气泡只有 1 个不重复；工具调用分片到达后正确执行并回填；最终 `assistant` 事件内容与流式内容一致。
- `diagnosis:e2e`（真实 Renode）exit 0，结论与 `matchedKbSteps:[3]` 不变。

### 残余

- 增量按 60ms/400 字符批量落盘，不是逐 token：每条事件都要 fsync，逐 token 会把一次回答变成上百次磁盘同步。
- 非 OpenAI 网关若流式协议不同（本项目只保证 OpenAI 兼容形态），会因帧解析失败退回 `invalid_response`，而不是自动退回一次性响应——`stream:false` 可显式关闭。
