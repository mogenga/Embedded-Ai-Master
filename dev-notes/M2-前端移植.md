## 背景与结论

`prometheus-frontend/` 是 Electron 桌面前端（renderer 5848 行、host 3444 行），协议是 NDJSON over stdio，与当前内核的 HTTP/SSE + 会话日志模型不同。本轮按用户选择：**双形态**（Electron 桌面 + 浏览器）、**直接替换**旧 Preact 工作台、**隐藏未支持项**而不伪造、代码放 `desktop/`、设置页只保留 UI 偏好、Electron 由用户安装。

## 被拒绝或纠偏的内容

- **不引入 Vite / Preact**：目标前端是纯 ES 模块、无构建步骤；`build:web` / `dev:web` / `test:ui` / `typecheck:web` / `verify:ui` 全部删除而不是保留空壳。
- **不伪造未支持能力**：git/PR/终端/worktree/packs/browser/skills/… 的入口从 DOM 里隐藏（保留节点、`hidden` 属性），宿主与 bridge 对这些命令回显式 `notice`（R3）。
- **不保留「始终允许」**：内核审批桥只有单次 allow/deny，持久规则不存在，按钮不渲染（渲染出来就是会失信的承诺）。
- **不伪装上下文占用率**：内核只给花费不给占用，百分比隐藏而不是编一个（D-165）。
- **不把阶段 4 的回放/导出/设备控制顺手做掉**：那三节原设计基于已删除的 `src/ui`，本轮只登记为待重写（D-166）。

## 翻车与返工

1. **Windows 动态导入路径**：`import(path.join(...))` 把 `E:\...` 当成协议名 `e:`，宿主启动即 fatal。改用 `pathToFileURL(...).href`。
2. **`createRunner` 未定义**：重构时把构造逻辑抽成函数却忘了加定义，`init` 直接抛 `createRunner is not defined`。补上后握手恢复。
3. **bridge 的 `session_loaded` 抹掉了用户消息**：`prompt` 成功后发 `session_loaded{messages:[]}`，渲染层按它重建转录，把提交时已画出的用户气泡清空（浏览器实测 `userTurns: 0`）。改为：只有切换会话才重建转录，新建会话只发 `state`。
4. **`adoptSession` 冲掉 running 标志**：`ctx` 被重建后 `running` 归零，`stream_end` 不再补 `run_end`，一轮永远处于忙碌。恢复标志后收尾正常。
5. **会话侧栏不展开**：`state.cwd` 为空时分组键对不上，已打开会话的项目折叠。改为从会话列表里取当前会话的 `workdir` 作为 `cwd`。
6. **侧栏标题为空**：内核 header 没有 title 字段，列表接口也不给标题。改为读首条 user 事件并缓存（上限扫 30 条，避免大 home 卡顿）。
7. **`always` 按钮被重新显示**：渲染层 `permission_request` 分支会把所有 `[data-permission]` 按钮设为可见，覆盖了 HTML 里的 `hidden`。改为只显示 `yes`/`no`。
8. **KB 回归用例在并发下超时**：并行跑满 worker 时单次检索可达数秒，5s 默认超时误报。给三个检索用例单独 30s 超时；单跑与两 worker 均全绿。
9. **测试用假网关 400 而非拒连**：拒连会触发 5 次指数退避（约 27s），用例超时。改用本地 HTTP 400 网关，失败立即返回。
10. **favicon 404**：静态根没有 favicon，浏览器控制台报错。加 `data:` 内联图标。

## D-164 修复：token 级流式（2026-10-20 第二轮）

用户要求：「D-164 无 token 流式进行修复」。

### 做了什么

1. **模型适配层支持流式**（`src/model/openai.ts`）
   - 请求体默认 `stream:true` + `stream_options.include_usage`。
   - 按 SSE 帧解析 `delta.content` 与 `delta.tool_calls`（参数分片累积，id/name/arguments 分别拼）。
   - 响应形态三态判定：`Content-Type: text/event-stream` → 流式；首行是 `data:` → 流式（兼容漏发响应头的网关）；否则一次性 JSON。
   - 网关用 400/404/405/415/422 拒绝流式时，降级为一次性响应并在**该 provider 实例**内记住结论，不再试探。
   - 已经把增量交给上层之后不再重试（重试会把同一段文字再送一遍）。
2. **内核落盘增量**（`src/loop/assistant-delta.ts` + `src/loop/query.ts`）
   - 新增 `assistant_delta` 事件（`{text}`），按批落盘：默认 60ms 或 400 字符。
   - `assistant` 事件仍承载这一轮的完整内容；投影层（`buildMessages`）忽略 delta，只用 `assistant` 重建模型上下文。
   - 写失败被吞掉并计入 `dropped`：同一轮的完整内容在 `assistant` 事件里，增量只是提前显示。
3. **协议层与前端**（`desktop/renderer/protocol.js`）
   - `assistant_delta` → 渲染器 `assistant_delta`。
   - 完整 `assistant` 事件只补齐**尚未流式过**的部分（用 `ctx.streamedText` 比对），不重复已显示的文本。

### 翻车与返工

1. **流式 tool_calls 的 wire 形状不对**：累积出来的对象缺 `type`/`function` 包装，被 `parseToolCalls` 判成「malformed tool call」。改成累积后还原成 OpenAI wire 形状，走同一套解析规则。
2. **降级缓存放在模块级**：一个网关的结论会污染另一个（并发跑不同 baseUrl 的测试会串），且让测试依赖执行顺序。改成 provider 实例级状态。
3. **JSON 路径会丢首块字节**：形态判定可能要等到第二个 chunk 才出结果，第一块被 `jsonChunks.push` 之外丢弃。改为原始字节始终保留。
4. **形态判定函数太脆**：只看第一行，遇到 SSE 的 `event:` 行或注释行会误判成 JSON。改为多行扫描并跳过 `:` 开头的注释。
5. **测试断言写错**：「降级后不再试探」用例期望 1 次一次性请求，实际是 2 次（两次 complete 各一次）。行为是对的，断言改对。
6. **`dropped` 按字节还是字符**：实测「丢失」是 2 个字符，断言写成 3。断言改对，并注明按字符计。

### 验证

- `npm test`：73 files / **1888 passed / 1 skipped**（skip 为需 `HARNESS_COMPAT_LIVE=1` 的 live 用例）。
- `npm run typecheck` / `build` / `build:mcp` / `test:mcp`（219）全 exit 0；`coverage` lines 93.23%。
- 新增测试：`tests/openai.test.ts`（流式 9 例：逐帧 delta、流式 usage、流式 tool_calls、漏发 Content-Type、网关拒绝降级、降级后不重复试探、非法帧、缺 choices、`stream:false`）、`tests/assistant-delta.test.ts`（5 例）、`tests/events-producers.test.ts`（增量落盘 4 例）、`tests/desktop/protocol.test.js`（增量映射 4 例）。
- 浏览器实测（无头 Chromium + 本地 SSE 网关）：回答**逐段出现**（采样长度 1 → 4 → 5 → 8 字符），气泡只有 1 个不重复；工具调用分片到达后正确执行并回填；最终 `assistant` 事件内容与流式内容一致。
- `diagnosis:e2e`（真实 Renode）exit 0，结论与 `matchedKbSteps:[3]` 不变。

### 残余

- 增量按 60ms/400 字符批量落盘，不是逐 token：每条事件都要 fsync，逐 token 会把一次回答变成上百次磁盘同步。
- 非 OpenAI 网关若流式协议不同（本项目只保证 OpenAI 兼容形态），会因帧解析失败退回 `invalid_response`，而不是自动退回一次性响应——`stream:false` 可显式关闭。

## 第四轮：内核↔前端联调核查与第一批修复（2026-10-21）

用户要求：「核查当前内核存在但未与前后端联调的功能。如模型配置，会话管理。当前只列举，不改代码」。列举完成后追加：「按优先级直接修，不走 superpowers，不准提交」。

### 做了什么

**核查（只读）**：逐个读 `src/index.ts`、`src/server/*`、`src/config/providers.ts`、`src/permissions/*`、`src/mcp/*`、`src/session/*`，与 `desktop/host/host.js`、`desktop/renderer/{bridge,protocol,app,settings}.js` 对照，列了 33 条断点。

**修复（第一批，均有离线测试）**：

1. **审批条读错形状**（最重）：内核 `approval_request` 带 `paramsPreview/paramsDigest/preset/deadlineAt`，协议层原样转交，但 `renderPendingDiff` 只认 `before/after/path`（diff 形状）→ 批准写操作时参数框是空的，R2「写前声明」在 UI 上不成立。新增 `renderPendingParams` 渲染 `paramsPreview`，另加 `deadlineAt` 倒计时（`startPendingDeadline`），10 秒内转 warn 色。
2. **浏览器 `setMode` 是假控件**：原来只改本地 `stateMode` 再发 `state` 事件，内核预设不变。给 `ActionInput` 加 `mode`，`runSession` 的 `permissions.preset` 用它覆盖；`POST /api/actions` 透传并映射 `invalid_mode → 400`；bridge 的 `setMode` 在下一条 prompt 里带上，运行中拒绝切换。
3. **浏览器追问重放整段历史**：`startPrompt` 固定 `openStream(-1)` 且重建 ctx 时 `lastSeq=-1` → 每次追问把整篇日志重新翻译一遍。改为捕获 `const since = lastSeq`，`ctx.lastSeq = since`，`openStream(since)`；`adoptSession` 一并设置 `ctx.lastSeq`。
4. **bridge 补缺口检测与重接上限**（D-167 第 1 条）：`seq > lastSeq + 1` → 关闭旧流、重拉 `/api/sessions/:id`、重建转录（≤3 次）；`stream_error` 从实际游标续接（≤3 次）后明说「已停止重试」。
5. **桌面 `getSettings` 回占位值**：`theme:"dark"` / `fontScale:1` 等硬编码，而 `fillSettings` 无条件 apply → 打开一次设置就重置全部显示偏好。host/bridge 改为只回自己有真值的字段，`fillSettings` 改为跳过 `undefined`。
6. **「跟随系统」主题被固化**：boot 把 `system` 解析成 light/dark 再 `setTheme` 写回 localStorage。新增 `setTheme(theme, {remember:false})`，boot 不再写回。
7. **`device_status` 链路错接**：协议层把它塞成 `board_state{selection:{}, projectKind:"unknown", device}`，而 `renderBoard` 读 `scannedAt/effective/project` → 面板永远是「正在扫描本机…」，chip 因 `relevant=false` 永远隐藏。改为独立 `device_status` 事件，板卡面板新增「设备」段（backend/probe/cpu/serial），chip 也能显示探针状态。
8. **usage 语义错位**：`usage` 事件是每次模型调用一条，renderer 覆盖式赋值却标「本次会话累计」。`updateMeter(..., {replace})` 区分 `state`（会话总计）与 `usage`（累加），`session_loaded` 带 `usageTotals(events)`。

### 全量结果

七路全部返回。几条子代理自己发现、值得记的：

- **内核文件树**（`listDirectory` / `registerWorkspaceRoot`）用 `Dirent` 判类型，只在 `DT_UNKNOWN` 时回退 `lstat`。500 项的目录逐项 `stat` 会明显变慢，而 Windows 上 `Dirent.isSymbolicLink()` 已足够可靠。
- **宿主**把 `files-api.js` 改成**命名空间导入** + 运行时 `typeof` 检查。理由是它构建期间内核导出还没落地，而参数解构会在 import 阶段就抛错、把整个宿主拖死。用命名空间后旧 `dist/` 只会让 `getTree` 回一条明确的 notice。这个防御是对的：`dist/` 是编译产物，宿主不该假设它和源码同步。
- **宿主**还发现 boot 工作区没被登记：`listDirectory` 只认已登记根，导致每次启动文件树对刚刚打开的工作区直接报「拒绝」。`init` 不能 await（会延迟 `ready`），于是把登记 promise 存进 `pendingRoot`，`getTree` / `setCwd` 先 `settleRoot()` 关掉竞态。这是 brief 没想到的一个真实缺口。
- **渲染器**发现一个跨形态 bug：`treeRow` 原先在 `api.send` **之后**才设 `pendingTreeTarget`，而浏览器 bridge 对支持的命令是**同步** emit 的，导致子目录内容被画进树的根部。改成先设后发。桌面宿主是异步的，所以这个 bug 只在浏览器形态出现——单测和桌面冒烟都不会暴露它。
- **渲染器**把空树文案写成「这里没有可列出的内容」而不是「这个文件夹是空的」。按契约，越界拒绝也是先 warn notice 再回空 tree，写成「空文件夹」会把拒绝伪装成事实。这是 R3 在文案层面的正确应用。

### 401 的根因：不是 bug，是设计缺陷

报错文案本身是**正确的**——它真的去查了那个名字的环境变量。问题是：

1. `providers.json` 的 schema 里**只有 `apiKeyEnv`，没有能存密钥本身的字段**。用户填的密钥既没保存也没被使用。
2. 原设计假设「用户会去 OS 层面设环境变量再重启应用」。对桌面应用这不现实。
3. 界面没有任何拦截——一个 32 位十六进制串填进「环境变量名」栏，照单全收。

修法：`apiKey` 字段 + `resolveProviderApiKey`（`apiKey` 优先，空值视为未配置）+ 密码框 + `looksLikeSecret` 当场警告。**警告不阻止保存**——提醒不是拒绝。

端到端验证：直接填的 `apiKey` 正确进入 `Authorization` 头，网关接受并返回模型列表；故意用错密钥时，网关在 401 响应体里回显了密钥原文，但事件流里**一个字都没有**（bridge/host 的 `redact`/`redactKey` 生效）。

### 浏览器打开文件夹：限制没有被突破，但不再假死

先说清事实：`showDirectoryPicker()` 只返回 `FileSystemDirectoryHandle.name`（裸文件夹名），浏览器出于安全**永不**暴露绝对路径。这条改不了。

原实现的两个真实缺陷：
1. 即使用户真的选了文件夹，也只弹一句警告就放弃，连 `handle.name` 都没用。
2. 没利用「服务端与浏览器同机」。

现在：`handle.name` → `POST /api/workspace/resolve` → 服务端有界搜索候选 → 1 个直接用 / 多个弹选择 / 0 个回落手输并区分「没找到」与「超出预算」。

**残余限制（必须如实说）**：主目录之外、且本次未登记过的目录仍然只能手输。搜索有深度 4 / 条目 20000 / 300ms 三重预算，超大主目录下可能 `truncated`。

安全边界没有放宽：只返回候选、**从不登记**；`allowedRoots` 一个字没改；只接受文件夹名（拒绝 `/`、`\`、`..`、NUL）；只 `readdir` 不读文件内容；不跟随符号链接；永不进入 `$HARNESS_HOME` 子树。

### B：KB MCP 补上 agentic 工具面

新增 `kb_glob(pattern)` 与 `kb_grep(pattern, glob?)`，`kb_read` 加分页（`offset` / `limit` / `totalLines` / `truncated`）。上限对齐实验 B：单次 100 条、单文件 2000 行、命中行截断 300 字符。`count` 报**真实命中总数**（可以大于返回条数），否则 `truncated` 之外的截断程度模型感觉不到。

我复核时改了两处：

1. **pattern 长度/段数上限**（256 字符 / 64 段，与内核 `src/tools/glob.ts` 同值）。这不是审美 —— glob 把 `**/` 编译成 `(?:.*/)?`，每一段都是回溯时的一个可选出口，而 pattern 来自模型输出，不是可信输入。D-086 已经因为这个在 `src/tools/glob.ts` 里加过同样的上限，新工具不能开一个新口子。补了单测（超长 / 超深 → `invalid_pattern`，边界仍可用）。
2. **glob/grep 不再先收集再截断**（D-078 的同一个坑）：命中数超过返回上限后只计数、不再留文本。`kb_grep(".")` 否则会把整份语料的每一行都复制一遍。`count` 语义不变。

**部署形态 ≠ 实验里被测量的 B**，这一点 B 在 README 里写明白了，我认可这个口径：实验 B 的工具面只有 `glob/grep/read/submit`，没有 `kb_lookup`；这里部署的是 lookup 首跳 + agentic 循环。因此 **0.925 不能算到本部署头上**，本部署也没在 B 的评测协议下跑过。B 的 H7（KB 外查询拒答）在实验里是整块未评估的 —— 而新加的两个工具**没有任何拒答机制**，命中与否全由字面匹配决定。这条已登记 **D-179**，不是修一个阈值就能解决的：正则命中数不是可用的置信度信号，拿一个没测过的数字调阈值比不调更糟。

### 各项的根因与修法

**② 顶栏不跟会话目录（D-182）**——根因不是「漏接线」，是**两条事件对同一个事实说了两种话**：`handleLoadSession` 把会话 header 的 workdir 正确放进 `session_loaded.cwd`，但紧接着 `stateEvent()` 用的是宿主模块级 `cwd`（只在 `init`/`setCwd`/`setWorkspace` 更新），而渲染器 `case "state"` 里 `state.cwd = message.cwd` 是**无条件覆盖**，后到的那条赢。浏览器形态没有这个 bug（`bridge.js` 的 `currentCwd = header.workdir` 在 `emit(stateEvent())` 之前）。连带症状：`getTree` 的 "." 解析到旧目录、`getFile` 的 `allowedReadRoots()` 只含旧 `cwd`。

新增 `adoptSessionWorkdir` 用**单个 `statSync`**（不 `exists` 再 `stat`——两步之间目录可能消失）判定，并按 errno 区分措辞：`ENOENT`/`ENOTDIR` → 「已不存在」，非目录 → 「不是目录」，其他 → 「无法访问（EACCES）」。把「读不了」说成「不存在」和把「失败」说成「成功」是同一类问题。**不重建 runner**：`handlePrompt` 新建会话时显式传 `cwd`（覆盖构造默认值），续聊不传（内核读 header），所以采纳的目录就是下一个新会话的目录，而重建会丢状态。

**③ 会话行右缘重合**——`.session-meta` 是 `position: absolute; right: 8px`，`.session-more` 是 `margin-left: auto` 的 20px flex 项，两者钉在同一条右边缘。修法是让 meta 在 `:hover` / `:focus-within` 时让出 `calc(9px + 20px + 6px)`（行右内边距 + 按钮宽 + 间隙）。

**这一条我自己重测了一遍**，因为子代理报的「修复前」表格是它自己造的数：`.session-more` 平时是 `display: none`，**隐藏元素不可聚焦**，`el.focus()` 根本不会触发 `:focus-within`。第一次量出来 `moreLeft: 0`（零矩形），说明它量的不是真状态。改用 CDP 的 `CSS.forcePseudoState` 强制真实 `:hover` 后才对上：

```
WITH FIX        meta.right 216 | more.left 222 | overlap false | gap -6（即 6px 间隙）
FIX NEUTRALISED meta.right 243 | more.left 222 | overlap TRUE  | 20px
```

「修复后不重叠」如果只在修复后的代码上量，等于**没证明修的是什么**。把修复在运行期覆盖回去、同一个页面同一个指针再量一次，才说明这条改动真的消掉了一个真实的重叠。

**④ 删「回退到这里」**——先核实内核有没有这个能力：`src/` 里只有 compaction 用的 `checkpoint` 事件，**没有日志截断、没有文件快照**；宿主 `handlers` 里没有 `rewindTo`。按 R3 删按钮，不在宿主里假装成功。删完 `grep -rn "rewind" desktop/renderer` 0 命中。

顺带发现**检查点面板整块是死代码**：`renderCheckpoints()` / `state.checkpoints` / 「全部恢复到本轮开始」全都还在，但 `getCheckpoints`/`restoreCheckpoint` 在两个宿主里都没有 handler，`history` 也不在 `SUPPORTED_PANES` 里——那个面板永远打不开。本轮**只记录不动**（和 rewind 是同一类问题，但删它超出用户点名的范围）。

**⑤ 表格与分割线**——渲染器**根本不产出** `<table>` 和 `<hr>`。`.markdown table/th/td` 的样式一直在 `styles.css` 里，是**死代码**：样式写了，没人产出那个标签。这类「有样式没实现」比「完全没做」更难发现——看代码会以为已经支持了。

表格切列用手写状态机而不是正则：`\|` → 字面竖线、反引号内开合不拆列、其余反斜杠原样保留（`C:\Users` 不能被吞）。分割线放在列表规则**之前**判断，否则 `- - -` 会被当成「bullet + 文本」；`paragraph.length === 0` 时才产 `<hr>`，所以 `上面一行\n---` 不会吃掉正文（setext 语义）。26 例测试，先红后绿。

**⑥ 查找 README.md 没从项目根开始（D-181）**——这条是我用**用户自己的会话日志**而不是猜测定位的。`~/.harness/sessions/<id>/session.v1.jsonl` 里模型调的正是 `glob {"pattern":"**/README.md"}`，返回 `(no matches)` + `[scan truncated at 5000 files]`，而那个项目根下就有 README.md。

只读复现（不写任何文件）：旧 DFS 命中 **0** 次；BFS + 新忽略清单命中第 **4** 个文件。该目录未被忽略的文件共 **25089** 个；根条目字母序里 `.mypy_cache/`、`.pytest_cache/`、`.venv/` 都排在 `README.md` 之前，旧 DFS 一进 `.mypy_cache` 就递归到 `altair/…` 深层把预算耗尽。**结果是"项目里没有这个文件"，真相是"我没找到那里"**——R3 意义上的假否定。

修法是三件事一起：忽略清单扩到 24 项 + `*.egg-info`；遍历改**惰性 BFS**（队列只存目录，出队才 `readdir`）；截断时在既有那行之后追加「结果不完整 + 怎么收窄」。`[scan truncated at 5000 files]` **原文保留**——README 与既有测试依赖它，改文案会连带改契约。

D-080 的保守语义显式保住了：BFS 下「预算已满但队列里还有未访问目录」不再由条目循环覆盖，`while` 顶部补了一道检查，否则会退化成「队列里剩个空目录也不算截断」。

**⑦ Agentic Search**——按 D-179 的建议 **① 与 ②**，**没有**做 ③（负样本跑批），所以 **D-179 不关闭**。`kb_grep` 加了 `fileCount` / `files`（命中最多的前 10 个文件），工具描述写死「命中只是候选，断言前必须 `kb_read` 原文确认」。**没有**加 `score`/`confidence`，也**没有**设任何阈值。

子代理给的判断我认可并原样保留：集中度信号**不够替代置信度**，三条理由——①**无方向**（1 个文件 25 行的真答案与 1 个文件 25 行的无关文档在 `files` 里长得一样）；②**没有绝对标度**（`fileCount: 3` 在 108 文件语料里算集中、在 5 文件语料里算散落）；③grep 连语义相邻都不保证。所以本轮的产出只是**把不可见的歧义变成可见的数字**。

### 我自己抓到的、子代理没看到的

**全量测试唯一的红是我修的，不是本轮任何改动引起的。** 一次全量 `npx vitest run` 后：`1 failed | 2403 passed | 3 skipped`，唯一失败是 `tests/assistant-delta.test.ts` 的「超过 maxChars 时立刻落盘」。

子代理判定它是「既有 flaky」（三次跑 failed/passed/failed）。**这个判断不成立**。我单独连跑 5 次，**5 次全红**——它不是并发抖动，是稳定失败。继续查：用例先 `sleep(10)` 再断言至少一条 delta，而 `session.append` 是带 fsync 的真实写盘。实测首次落盘：

```
countAt10ms: 0   seenAt: 18.0 / 18.4 / 19.5 / 24.8 / 25.5 ms
```

**10ms 时一律 0 条**——这条用例测的是这台机器的磁盘速度，不是「超限不等 flush」这个行为。改成 `vi.waitFor` 轮询。

改完还要证明新写法**仍然抓得住回归**：故意把 `push` 的超限分支改成 `schedule()`（退回定时器路径），用例立刻变红；探针随后完整回滚，`git diff src/loop/assistant-delta.ts` 为空。**只证明"绿了"是不够的，得证明它在该红的时候会红。** 登记 **D-180**。

另有一次误判值得记：子代理 D 报 `tests/assistant-delta.test.ts` 是 flaky 时，理由是「三次跑 failed/passed/failed」。这条证据看起来像抖动，实际是**每次运行的环境不同**（有时并发、有时不并发）。同一个文件在同一环境下连跑 5 次全同色，才是判据。

### 残压

- **`bridge.js` 对已消失的 workdir 不校验**，浏览器形态会把 cwd 指向一个不存在的目录，顶栏显示已删除的项目。桌面端现在更严格，两端在这一个边角上不一致（记在 D-182）。
- **检查点面板整块是死代码**（无 handler、pane 不可达），未删。
- **`.session-more` 用 `display: none → flex` 切换**，悬停瞬间标题宽度会跳变（实测 183px → 155px），长标题会重新省略。既有行为，未改（改成常驻 `visibility: hidden` 会改变 Tab 顺序语义）。
- **`grep` 仍是同步正则（D-085）**、仍先收集全部命中再排序截断（D-078）；BFS 队列内存 O(宽度)。
- **忽略清单一式两份**（内核 `src/tools/fs-walk.ts` 与 `mcp-servers/kb/service.ts`），会各自演化。
- `dist/` 与 `dist-mcp/` **仍是旧的**：本轮改了 `src/tools/*` 与 `mcp-servers/kb/*`，要在真实运行里生效必须先 `npm run build && npm run build:mcp`（未执行）。
