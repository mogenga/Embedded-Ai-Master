**核心决策**

- 总线实现为**会话日志投影**：append-only JSONL 是唯一事实源，`LogTailEventSource` 读历史并 200ms 轮询增量；不引入进程内 EventEmitter/共享内存。
- 单会话 SSE：`/api/events?sessionId&since`，支持 `Last-Event-ID`、补播+跟随、心跳、慢消费者背压与 `stream_end`。
- 新增 `tool_started`、`mcp_status`、`device_status`；`tool_result`/`permission_decision` 复用。
- 设备状态只来自 MCP `structuredContent.deviceStatus`；`state` 是领域无关 JSON，UI 只做已知字段 patch，不推断。
- 证据不单列事件：`tool_result.payload.evidence/artifactPath/detail` 已承载。
- 本轮不做 Web 审批 API/UI、全局多会话流、进程内低延迟适配器。

**Review 结论**

- Builder check 提出 6 个问题（MCP 状态 kind、设备面板重建、活跃会话半行、补播队列、evidence、mcp_status 失败语义），已写入 spec/plan。
- 第一轮独立 review 发现 5 个 blocker + 12 个 major，已修复：
  - `/api/sessions/:id` 对 open 会话仍严格读取，运行中首次打开 Web 会 500；改为容错快照。
  - `McpCallResult` 未透传 `structuredContent`；补 manager 通道。
  - `read`→`follow` 交接窗口会丢事件；follow 先发快照事件并使用快照 offset/pendingTail。
  - 事件源缺少 realpath/symlink 包含性校验；补安全边界。
  - `device_status` 写失败会重复 `tool_result`；先推进 pending 再写状态。
  - `onToolStarted` 缺 access、可能产生孤儿 started；改为执行前逐调用回调。
  - MCP 11 种 kind 与 `name/originalName/scope` 迁移；客户端游标单一所有者；旧流关闭/sessionId 过滤；follow 错误→`stream_error`；UTF-8/截断测试；端到端 SSE 测试。
- 第二轮复核：15 项全部 ADDRESSED；新增 5 个 major（快照 offset、旧 status 映射、onGap 接线、stream_error 重连上限、drain abort 竞速），已补入 plan/spec。

**被拒绝或纠偏的内容**

- 未采用“从工具名/参数推断设备状态”。
- 未采用独立 `evidence` 事件（本轮）。
- 未把 Web 审批 API/UI 纳入本轮。
- 未引入进程内事件总线或全局多会话流。

**翻车与返工**

- 首版 spec 让 SSE 容错但详情接口仍严格，运行中首次打开 Web 仍会失败；改为 open 会话统一容错快照。
- 首版 plan 未发现 `McpCallResult` 没有 `structuredContent`，设备状态无法显式发布；补 manager 透传。
- 首版 follow 从文件末尾开始，read→follow 窗口会丢事件；改为先发快照事件并携带 pendingTail offset。
- 首版并发批次在授权阶段预写 tool_started，第二条失败会留下孤儿；改为执行前逐调用写。
